3. 时间基准唯一：分镜稿、filmstrip、标注、对照高亮全部读 timeline.json 的 start/duration。
4. 密钥脱敏回显：GET /api/settings 对 api_key 打码；PUT 时含「…」或空串保留旧 key。
5. 阶段 7 关键帧渲染前按 4.5 字/秒估算时长；阶段 9 强制校验音频文件真实存在（防止把估算当 TTS 完成）。

## v1.1 新增设计：资料摄取（飞书文档 / 公开网页 → 整理 → 喂给视频流水线）

### 需求定位

Agent 能读取用户给的飞书文档链接与公开网页链接，抓取正文并由 LLM 结构化整理；整理结果既是独立产物（侧栏可读），也可作为视频制作的参考素材注入创意/分镜阶段。对应 skill 中 Kimi「整理资料」的既有职责。

### 能力拆解与方案

**1. 公开网页读取（无需配置，开箱即用）**
- 新模块 `backend/app/ingest/web.py`：httpx 抓取 → trafilatura 提取正文（标题/正文/发布时间）→ 正文落盘 `references/web_<slug>.md`。
- 反爬边界：403/验证码/JS 渲染页如实报错，不伪装"无内容"；微信文章等带防护页面按实际响应标注失败原因。
- 依赖追加：`trafilatura`（进 requirements.txt）。

**2. 飞书文档读取（需用户配置应用凭据）**
- 新模块 `backend/app/ingest/feishu.py`：解析链接中的 doc token（支持 `/docx/`、`/docs/`、`/wiki/` 路径；wiki 先换 obj_token）→ `app_id + app_secret` 换 `tenant_access_token` → 调 `GET /open-apis/docx/v1/documents/{id}/raw_content` 取正文。
- 设置页新增「飞书应用」配置区：`feishu_app_id` / `feishu_app_secret`（与供应商 Key 同规则：只存服务端、脱敏回显、PUT 保留旧值）。
- 权限前提（写入设置页提示文案）：文档需对应用可见（文档分享给应用或应用开通相应文档权限）；401/403/权限不足如实报错并给出排查提示。
- 不去做的：不接管飞书消息/多维表格等全域能力（那是独立插件的领域）；wiki 知识库仅支持单文档读取。

**3. 整理与产物**
- 抓取正文后由「对话理解」阶段配置的模型做结构化整理，只输出产物 + 流式摘要：
  - `{"title","source_url","ingested_via":"web|feishu","summary":"200 字摘要","key_points":["…"],"usable_facts":["可作视频素材的事实/数据/案例"],"suggested_angles":["可能的讲解切入"]}`
- 整理产物注册为 `doc` 类型 artifact（logical_name=`ref_<slug>`），来源字段如实标注 URL 与摄取通道，进侧栏。
- **接入视频流水线**：`brief.json` 增加 `references` 字段（整理产物 id 列表）；阶段 3（创意）与阶段 4（分镜）的提示词注入 `usable_facts` + `key_points`；事实校对阶段把参考资料列入核对范围，防止分镜虚构资料里没有的数据。

**4. 对话入口**
- 用户消息中检出 URL（正则 `https?://\S+`）→ 自动判断域名：`feishu.cn`/`larksuite.com` 走飞书通道，其余走网页通道 → 抓取 + 整理流式输出 → chips 提示 `[用这个资料做视频] [再读一篇] [查看整理产物]`。
- 也支持显式指令：「读一下这个链接并整理」「把这几篇资料汇总成一个选题」。
- 多篇资料可汇总：chips 动作 `merge_refs` 把当前会话的全部整理产物合并为一份选题简报。

### API 与数据流

```
POST /api/ingest            { session_id, url }          → SSE：抓取进度 + 整理流式输出 + artifact 事件
GET  /api/projects/{pid}/references                      → 当前项目引用的资料列表
POST /api/projects/{pid}/attach_ref { artifact_id }      → 把整理产物挂到项目 brief.references
```

数据流：URL → ingest 模块抓正文 → LLM 整理 → artifact 落盘注册 → 用户 chip 选择「用这个资料做视频」→ attach_ref 写入 brief.references → 创意/分镜提示词注入。

### 里程碑（追加 M6，预估 1.5–2 天）

| 内容 | 验收标准（逐项实测） |
|------|---------------------|
| 网页摄取 + 整理 + 产物 | 3 个不同类型公开页面实测：正文提取完整、整理 JSON 字段齐全、失败页如实报错 |
| 飞书摄取（凭据配置） | 真实飞书文档链接实测读取成功；无权限文档返回明确权限提示而非空内容 |
| 资料接入流水线 | 用整理产物做视频：brief.references 写入正确，创意/分镜产物中出现资料事实且校对通过 |
| chips 与汇总 | 含 URL 消息自动触发摄取；merge_refs 汇总产物字段完整 |

### 风险与对策

| 风险 | 对策 |
|------|------|
| 飞书权限模型复杂（用户搞不懂分享/授权） | 设置页写清最短授权路径；报错信息区分「应用凭据无效」与「文档未授权给应用」 |
| 网页正文提取质量参差（列表页/视频页/防爬） | trafilatura 为主；提取结果过短（<200 字）时明确提示「可能提取不全」并附原文前 500 字供用户判断 |
| 整理模型幻觉（编造资料里没有的内容） | 整理提示词强制「只许使用原文信息」；usable_facts 逐条要求能回溯原文；校对阶段把分镜与资料比对 |
| 大文档 token 超限 | 正文超过阈值（暂定 3 万字）先分块整理再合并，保留分块中间产物 |

## v1.2 新增设计：前端体验重设计（M7，预估 1.5–2 天）

**布局重构（对标 Kimi/GPT 的信息层级）**
- 左侧可折叠会话栏（240px，含搜索/新建/分组按时间：今天、昨天、更早）；当前顶栏会话标签改为侧栏列表。
- 中间对话列居中（max-w-3xl）：用户消息右侧圆角气泡、助手消息无气泡纯文本 + 左侧 Agent 图标列（GPT 式）；流式输出光标改为柔和的渐变点。
- 输入区改为悬浮卡片：大圆角（rounded-2xl）、柔和阴影、聚焦时边框高亮微光；chips 收纳进输入框上方一行，超出折叠。
- Header 改为玻璃拟态（backdrop-blur + 半透明底），状态徽标保留。
- 右侧产物面板保留现有结构，跟随新 token 体系换肤。

**色彩系统重构（当前硬编码颜色的根治）**
- 所有颜色收敛为语义 CSS 变量双套 token（`data-theme="dark"|"light"` 挂在 `<html>`）：
  - dark 沿用现行 `#0B1220/#5DE2E7` 体系微调；
  - light 新建：背景 `#F7F8FA`、面板 `#FFFFFF`、文字 `#1A2333`、强调色同系降饱和版 `#0E9BA8`。
- 切换入口在 Header（太阳/月亮图标），`localStorage` 持久化，首次访问跟随 `prefers-color-scheme`。
- 组件内禁止出现裸 hex（构建后 grep 验收，白名单仅 index.css token 定义处）。

**设置页输入框统一规格（修复大小不一）**
- 抽公共 `Field`/`Input`/`Select` 组件：统一 height 36px、px-3、rounded-lg、text-sm（Key/URL 用 mono text-xs）、border 同色同宽。
- 供应商卡片改为固定两列 grid（`grid-cols-[1fr_120px]` 等），所有输入/下拉等高等宽；配音区同样走 Field 组件。
- 验收：设置页截图逐个量 input 高度，全部一致（36px）。

### 需求 2：会话改名

- 后端：`PATCH /api/sessions/{sid} {title}`（trim + 长度上限 50）；首条用户消息发送后自动以「消息前 20 字」命名（仅当标题仍为「新对话」）。
- 前端：侧栏会话项悬停出现「重命名」图标 → 行内 input（Enter 保存 / Esc 取消）；移动端长按触发。
- 验收：改名后刷新页面标题保持；自动命名只触发一次不覆盖手动改名。

### 需求 3：设置弹窗防误触

- 移除 backdrop 点击关闭；关闭入口只留右上角 X 与底部「取消」按钮。
- 新增脏状态检测：表单相对已加载快照有改动时，点 X/取消弹出二次确认「有未保存的修改，确定放弃？」（自绘小确认条，不用原生 confirm）；无改动直接关闭。
- Esc 键行为同 X（纳入二次确认逻辑）。
- 保存成功给 toast 反馈（现有「已保存」文字升级为右上角浮出 toast，1.5s 自动消失）。
- 验收：无改动时点 X 直接关闭；有改动时点 X/取消/Esc 均弹确认；backdrop 点击无任何反应（自动化点四周各一次断言弹窗仍在）。

### 需求 4：供应商连接测试

- 后端：`POST /api/settings/test_provider`，入参为**表单当前值**（不要求先保存），用该配置发起最小真实调用（`max_tokens=8`，固定 prompt「ping」），返回 `{ok, latency_ms, model_echo, error?: {kind, detail}}`；错误分类沿用 llm.py（auth/permission/timeout/network/http/empty），Anthropic 与 OpenAI 兼容两通道都支持。
- 前端：每个供应商卡片加「测试」按钮 → spinner → 绿色 ✓ + 延迟毫秒数 / 红色错误类别与详情；测试 MiniMax 另设独立按钮（走 TTS 配置，发 1 秒以内短文本合成请求）。
- 测试不写入任何产物与日志密钥（请求日志不落 Authorization 头，继承 skill 纪律）。
- 验收：正确配置返回 ok+延迟；故意改错 key 返回 auth 错误且信息可读；未保存的表单值也能测。

### 阶段模型选择细化（v1.2.1，M6 后的盘点结论）

M6 引入新 LLM 调用点后，全部模型调用点共 8 个。按任务性质归并为 **7 个可选档位**（不是每个调用点一个选择，避免设置页膨胀）：

| 设置项（stage_models key） | 覆盖调用点 | 选型建议 |
|---|---|---|
| 对话理解 `clarify` | 需求澄清对话、项目问答 | 通用对话模型即可 |
| 任务路由与提取 `routing`（新增） | 简报提取、修改意图路由（阶段 12）、门禁自然语言判定辅助 | **便宜快**的小模型（结构化 JSON 输出，量大价廉优先） |
| 创意方案 `concept` | 阶段 3 | 强模型 |
| 讲稿分镜 `storyboard` | 阶段 4 | **最强模型**（决定视频质量上限，默认 Opus） |
| 事实校对 `factcheck` | 阶段 5 | 与分镜**不同家**模型（交叉验证，避免同源盲区） |
| 视觉代码 `visuals` | 阶段 6、修改模式的 visuals 重写 | 代码能力强的模型 |
| 资料整理与汇总 `ingest`（新增，M6） | 网页/飞书正文结构化整理、多篇 merge_refs 汇总 | **长上下文**优先（大文档分块后仍要合并） |

规则：
- 新增 key 的 fallback：`routing` / `ingest` 未配置时回退「对话理解」，再回退任一可用供应商（与现有 `_chat_provider` 逻辑一致）；不新增硬依赖。
- `store.py` 的 `DEFAULT_SETTINGS["stage_models"]` 增加 `routing`、`ingest` 两键（默认 None）。
- 归并理由：简报提取和修改路由都是小输出 JSON 分类任务，拆开没有收益；资料整理与汇总同理。7 档是「能感知差异」与「设置页可维护」的平衡点。
- 验收：设置页出现 7 个下拉；`routing`/`ingest` 留空时对应功能仍能用（回退实测）；各阶段产物来源标注与实际所用模型一致。

1. **修改失败静默死亡**：`run_modify` 的 `_apply_visuals_fix`（cc 重写 ~100s + 冒烟）期间零输出，且异常时仅 SSE error 一闪而过、不落盘。修复：分支执行整体 try/except——失败时播报「❌ 修改失败（kind）：detail」+ 落盘 assistant 消息（刷新后仍可见）+ 给出 suggestions + 正常 done（前端不再卡 busy）。
2. **失败覆盖可用代码**：`check_visuals_code` 自检前会先把新代码写入 visuals.py，修复耗尽时可用旧版已被覆盖。修复：`_apply_visuals_fix` 改为异步生成器逐段播报（重写中→自检中→每轮修复→通过），失败时**恢复修改前的 visuals.py**。
3. **关键帧重渲染后预览不更新**：`/api/projects/{pid}/file` 无缓存头，同名 PNG 被浏览器启发式缓存。修复：file 与 frame 端点均加 `Cache-Control: no-cache`（ETag/Last-Modified 回源校验，304 省流量）。
4. **「标注修改画面」名不副实**：关键帧画廊（GalleryView）每帧新增「修改这帧」按钮 → 内联编辑框（Enter 发送/Shift+Enter 换行/可取消）→ 以「【关键帧修改 第N镜·位置（文件名）】说明」格式进对话修改流；画廊顶部加操作提示。
